# Pokemon Black (IRBO): Black 2 (pokebw2) names for the functions of Black's that the shared
# Black 2 layouts watch (frontend/main.cpp, pickSceneBw2). tools/bw1/funcmap.py gives these
# functions the Black 2 name in Black's funcs.txt, so the shared code finds them unchanged.
#
#   <pokebw2 name>  <aletheia name>  <module> <address>  <how it was matched>
#
# Matched by tools/bw1/match_bw2.py (pokebw2 753b3fd, aletheia 0d05b6cc, both ROMs): "exact" =
# the same instructions with addresses masked; "alignN" = the same place between exact matches
# in the corresponding overlay, N = instruction similarity; "position" = by hand, see below.
# Every one also has the matching source file name in aletheia (btl_main.c, itemmenu.c, ...).
# ConfirmDialog_Update: Black's BMP_MENU_ProcessYesNo (bmp_menu.c), the one after
# BMP_MENU_CreateYesNo just as ConfirmDialog_Update follows ShopUI_CreateConfirmDialog (Black 2
# rewrote its body). BChoiceMain_Task: Black 2's choice screen (its overlay 289 is new in Black
# 2); its part, a YES / NO question on the touch screen in a battle ("Use next Pokemon?", "Give
# a nickname?"), is Black's BTLV_SCD choice screen, polled by BTLV_CORE_PollYesNoMenu every frame
# while it is up (Black 2's BtlvCore_PollYesNo): matched by role, "role".
# BtlvCore_WaitTargetSelect: Black's BTLV_CORE_PollTargetMenu, right after BTLV_CORE_StartTargetMenu
# as Black 2's follows BtlvCore_StartTargetSelect (the same size, 0x2c), between the move menu's
# functions and the input's abort. The level-up window's three waits (open, the new stats, close)
# are the second of each of Black's three pairs of 16-byte functions after the move-forgetting
# screen (aletheia's "BallWindow"), as Black 2's three pairs follow its move-forgetting screen,
# just before the fades. ShinkaDemo_Main: the evolution scene's main function, SHINKA_DEMO_Main
# in aletheia too. BtlvBGauge_Create, _SlideTask, _Delete: the bar of Poke Balls at a trainer
# battle's start (Black's BTLV_B_GAUGE_*PartyBallBar, the same three roles in the same order).
# StartMenu_Continue is Black's STARTMENU_StateConnectPrompt: the same C-Gear question as Black
# 2's (message, YES / NO; B gives a second "is that OK?" YES / NO whose YES leaves the C-Gear
# off; skipped at once when the C-Gear has not been obtained), so the shared code answers it
# the same way (B, then A) and the player never sees it.
